# 0.4.4 候选版：跨 ROM 回撤与模拟应用列表修复

主应用 0.4.4/code 8；LSPosed 模块 0.3.13/code 16；独立 Root 载荷 0.1.1/code 2。

**最新结论（2026-11-01）：小米 15 / Android 16 的亮屏 3 分钟检查通过；将本应用的厂商省电策略设为“不受限制”后，包含 60 秒熄屏的 90 秒检查也通过。默认自动省电会冻结主控进程并使模拟停止。此结论不代表 ColorOS 17 / Android 17 已通过，也不代表 Root 0.1.1 已完成本轮真机验收。**

## 反馈与证据边界

用户反馈一加 ACE6 / ColorOS 17 上 LSPosed 不生效，或 Root / LSPosed 模拟数秒后回到原位；另有 Android 17 / HyperOS 4 的开发者选项无法选择 Geostep。测试使用 GitHub 0.4.3/0.3.12；用户要求按最新版 LSPosed 排查。未取得故障设备的实际 API level、框架日志、回撤时运行状态或持续回调报告。版本名称按用户描述记录，不能据此认定已复现 Android 17 特定行为。

最初代码修复阶段没有连接 USB 设备，后续连接小米进行了下文的验证。以下代码修复不等于原始故障 ROM 已通过真机验收。

## 已确认的代码问题与修复

- 主应用缺少 `ACCESS_MOCK_LOCATION` 声明。补齐候选应用声明，供开发者选项选择；此声明本身不授予模拟权限，标准模式仍需用户选择 Geostep。Root/LSPosed 不依赖该选择。
- 安装成功判定仅看总钩子数。改为检查控制、最近位置、一次性定位、订阅、注销、回调交付等必需入口；辅助钩子不再充当成功证据。入口不全时拒绝启用，保留状态和停止命令。
- 安装只寻找固定的 LocationManagerService 类。增加对已发布的本地 ILocationManager 实例的实际类及父类遍历，支持厂商覆盖方法；同一服务调用经过父子类时仅应用一次策略。
- LSPosed 初始安装部分成功就不再重试。增加幂等安装和有界延迟重试，等待本地服务发布；重复成功的钩子不叠加。
- 监听器恢复依赖单一 getter 和固定字段层级。增加已知字段/getter/父类查找，并直接处理 LocationListenerTransport 交付，补足 Binder 方法被 AOT 内联绕过的路径。仍按接收方处理，保留权限检查及豁免语义，不修改全局 provider 缓存。
- 模拟前台服务未持有 CPU 唤醒锁。运行、暂停移动及启停命令处理期间采用 60 秒超时、20 秒续约的 partial wake lock；停止、失败和销毁释放。它不能保证 OEM 不冻结/杀死应用，保留进程失联后 15 秒自动停止。
- 模块静态说明仍写 0.3.10，现与包版本一致。明确其使用 libxposed API 102；本轮没有证据指向用户的 LSPosed 版本过旧。
- 诊断增加设备/API、关键钩子缺口、最近回执剩余心跳、过期次数和回调计数。计数不记录消费方包名、URL 或真实坐标；未匹配回调也可能来自非模拟接收方，不能单独当作回撤证据。

## 持续验收修正

旧 ProbeActivity 虽运行 20 秒，但仅保留每个 provider 前三帧，无法证明后半段没有回撤。新版记录全程，脚本默认持续 60 秒、支持 20–180 秒，任一错误坐标/错误 provider/超过 5 秒的回调缺口均判失败。旧报告仅作为首帧证据，旧探针 APK 不能冒充新版持续验收。

连接故障设备后，完整安装候选主包、对应模块及新版独立探针/测试包。系统已加载旧模块或 Root 载荷时，需用户手动重启；不得自动重启或改动热点。

```powershell
# LSPosed：用户启用模块和系统框架作用域后手动重启
./scripts/verify-compatibility.ps1 -Engine xposed -Serial <serial> -Extended -DurationSeconds 60

# 独立 Root：仍要求系统进程无驻留 LSPosed，按用户操作切换环境
./scripts/verify-compatibility.ps1 -Engine root -Serial <serial> -Extended -DurationSeconds 60
```

补测：开发者选项能否列出并选择 Geostep；标准模式自检；前台、切到独立探针、熄屏恢复三种条件下是否续租；停止后是否恢复真实定位。用户私有业务入口由用户自行测试，不要求其提供身份。

## 重启后 0.3.13 实测：亮屏通过，熄屏冻结仍需处理

后续用户重启后，system_server 更新为 PID3532，新鲜回执确认为模块 0.3.13，主应用 0.4.4。180 秒全程测试通过：GPS 181 帧（最大间隔 1018ms）、network 240 帧（1022ms）、fused 356 帧（1005ms），坐标/provider 错误均为 0。12 项基础检查、last/current/WebView、生命周期/flush/注销通过。GNSS/NMEA/传感器与动态豁免/停止/恢复/注销也通过（GNSS 报告 53 事件、动态策略 384 事件）。

**熄屏测试没有通过。** 两次均出现主应用 heartbeat 停止增长、随后模块 15 秒租约到期并关闭模拟。第二次在熄屏时采集到本应用 `cgroup.freeze=1`，同时仍为前台服务（procState=4），持有 partial wake lock。这证明控制进程被冻结；仅增加 CPU 唤醒锁不能解决本机的冻结策略。冻结的具体发起者（系统/厂商/其它管理组件）尚未确认。已记录的坐标样本未出现错误，测试因观察到模拟关闭而失败，不能混同为已捕获真实坐标回调。

试图只对本应用临时增加标准电池优化豁免后做对照，但安全锁屏阻止探针取得前台，按前台保护规则中止；豁免设置已恢复。该次不能用于判断电池豁免是否有效。需要用户解锁继续对照，不读取用户私人应用。

证据：工作区 `_tools/reversion-device/lsp-0313-after/`、`lsp-0313-extended/`、`lsp-0313-screen-off/`、`lsp-0313-screen-diagnostic/`、`allowlist-test.json`。收尾已唤醒屏幕并停止模拟；未自动重启、切换 LSPosed/Root 或操作热点。**不能将本版标为熄屏可靠或 ColorOS 问题已修复。**
