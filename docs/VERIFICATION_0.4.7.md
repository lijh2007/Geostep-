# 0.4.7 真机核验

主应用 0.4.7/code11，Root 载荷 0.1.3/code4；发行沿用 0.4.6 的可选 LSPosed 模块 0.3.14。测试使用实际发行的 39.14 MB 通用 Release APK，安装后摘要核对一致：

`7336c315718e66537976bee6236eeaa873ec6101c71bef3ccb0129a9183c03b6`

设备为小米 15 / Android 16 / API36 / ARM64。设备实际加载的是既有 **Geostep 模块 0.3.13**，并非新装 0.3.14；因此不将本次记录写成模块 0.3.14 的独立验收。系统存在其他定位模块，未改动它们的启用状态或作用域。

## 已通过

| 项目 | 结果 |
|---|---|
| 升级与启动 | 同签名覆盖 0.4.6，已有偏好和个人高德 Key 可继续使用；发行包非 debuggable |
| 地图 | 高德与 OpenStreetMap 实际显示正常；高德地点搜索和两点沿道路规划完成 |
| 路线 | 移动、暂停保持位置/零速度、继续移动、停止确认通过 |
| LSP 持续定位 | 180 秒，GPS 179 帧、network 181 帧、fused 353 帧，共 713 帧；错误坐标和错误 provider 均为 0 |
| LSP 更新间隔 | 最大间隔分别为 1032 / 1035 / 1007 ms |
| 公开接口 | last/current/updates、WebView、PendingIntent、取消、注销、flush 及 STOP 确认通过 |
| Root 授权 | 主应用内默认 su 检查实际返回 uid=0 |
| Root 载荷 | 从同一主 APK 提取并核对哈希，实际加载到自有独立进程；8 项钩子检查通过，原方法恢复，系统进程未重启 |
| 标准模式坐标 | 30 秒 GPS/网络定位返回的 65 个 fix 均符合预期坐标和 provider；标记差异见下一节 |

第一轮长时检查因测试接收方转入后台而未完成，不计入通过记录。增加前台检查后重新执行的完整 180 秒记录通过；未用不完整报告替代持续测试。

## 未完成与限制

- **标准模式首帧标记**：GPS 的一个初始缓存回调为 `isMock=false`，其余 GPS fix 和全部 network fix 为 `true`；坐标均正确。独立、未加入 Geostep 客户端作用域的探针也观察到这一现象，但对照轮次未完成全长采样。当前设备有多个系统定位模块并存，未进行停用其他模块后的干净环境对照，不能确认归因，也不宣称已修复该差异。
- **纯 Root 系统模式**：本轮验证了真实独立进程加载，不等于在无 LSPosed 环境中接管 `system_server` 已通过。Root 0.1.3 的完整纯 Root 系统复测仍待进行。
- Android 17 / ColorOS / HyperOS / 荣耀原始故障设备、第三方私有 SDK 和业务风控不在本次通过范围内。没有访问用户的私人网站、小程序或业务应用。
- 本次按以上已经通过的项目发行，保留这些未完成项；不作所有模式、机型和业务均兼容的承诺。
