## 2. 关键实现约定

- **授权与坐标边界**：高德 SDK 只在已有用户授权且配置有效时使用；每次地点服务调用检查持久化授权，撤回后停止新的调用。存储、模拟和界面接口统一使用 WGS 84，高德边界转换为 GCJ-02，返回结果再转回 WGS 84。
- **高德请求**：搜索和地址查询总预算 15 秒；SDK 连接/读取超时设置为 8 秒。驾车最多 16 个控制点，一次请求传入途经点；步行/骑行最多 10 点，逐段请求，总预算 30 秒。各路线请求要求返回折线与时间信息。
- **缓存和备用服务**：高德/开放搜索各最多 50 条、15 分钟；地址最多 20 条、15 分钟。开放搜索跨 Photon/Nominatim 总预算 12 秒，连接/读取各 4 秒。OSRM 驾车请求总预算 15 秒，最多 100 个途经点，16 条路线缓存保留 10 分钟。
- **取消与错误**：SDK 回调注销并隔离迟到结果，HTTP 等待可取消；用户错误信息不输出 Key 或原始请求。SDK 没有提供的网络中止能力不假定已经存在，取消后以“不再接受结果或更新 UI”为最低保证。
- **路线数据**：`route_point` 保存可播放的详细几何、海拔和入边速度；`route.controlPointsJson` 保存用户途经点，`route.profile` 保存 `drive/walk/ride`。导入或旧轨迹的控制点为空，避免把密集轨迹误当作手工途经点。
- **编辑语义**：反向后保留每条原始边的速度；移动或删除点仅使受影响边的速度失效，其他海拔、顺序和元数据保留。编辑或更改出行方式会取消过期规划，保存路线时一并保存出行方式。
- **兼容迁移**：v1→v2 仅新增 nullable `controlPointsJson`；v2→v3 新增 `profile TEXT NOT NULL DEFAULT 'drive'`。现有路线、位置、时间和点数据不删除；原来没有出行方式的数据采用旧有驾车默认。

## 4. Android 数据回归用例

`DataSmokeChecks(host: Instrumentation).run()` 供统一 instrumentation 入口的 `mode=data` 调用，不直接注册为另一套 runner。

用例仅创建随机名 `geostep-data-smoke-<UUID>.db`，不打开应用日常数据库，不读取或修改用户收藏/路线。测试建立与 v1 实体一致的四张表，插入旧路线及点、收藏和历史，然后通过真正的 Room 打开路径执行迁移，包含以下断言：

1. 独立 v1 SQLite 数据库建立成功。
2. Room 执行 1→2→3 并验证 schema；旧路线、点、收藏、历史字段保留，旧路线 profile 为 `drive`、控制点为空。
3. 保存含两个控制点、三个详细几何点的步行路线；关库重开后 profile、控制点、海拔、速度、seq 和 routeId 保留。
4. 编辑收藏只改变名称、坐标和海拔，保留创建时间、分组和精度。
5. 空名称、非有限海拔、未知 profile 被拒绝，未留下修改或部分路线数据。
6. 删除指定历史行不影响另一行历史、路线和收藏。
7. `finally` 关闭并删除独立测试库及 journal/WAL/SHM；清理失败使整体用例失败。

每步使用 `host.sendStatus` 发出 PASS/FAIL，最终通过 `host.finish` 返回结果；不会跳过失败或在未执行断言时返回成功。

在用户安排恢复设备测试、构建并安装最新测试 APK 后，统一入口使用：

```text
adb shell am instrument -w -r -e mode data com.geostep.app.test/com.geostep.app.DeviceSmokeInstrumentation
```

此处仅记录未来执行方式，本次离线收尾不执行该命令。地图服务检查同样应使用统一 runner 的 `-e mode map`，而不是直接调用 `MapSmokeInstrumentation` helper 类。

## 5. 后续设备验收边界

设备重新接入后，优先核对三项：高德/开放地图冷启动与重复打开时间、真实搜索和三种路线规划的结果及耗时、`mode=data` 的实际 Android 数据回归。数据库测试通过前不声明迁移已在手机完成验证；搜索/路线测量完成前不宣称“已提速多少”或“全部秒开”。

高德 native SDK 当前提供 ARM32/ARM64，x86 环境应使用开放地图。地图服务仍依赖网络、有效服务配置及供应商可用性。最终版的地图和 Geo 统一使用 `AmapCoordinates`：正向调用官方 SDK GPS 转换，逆向反解同一函数并检查收敛，不再依赖 core 的手绘覆盖轮廓。覆盖边缘附近无法确认逆向结果时会报错，不保存未确认的坐标；新增的 10 个 SDK 边缘样本设备测试尚未执行。

最终源码另已修复：地图手势退出跟随后不会再被旧动画拉回；旧实例回调和排队预览失效；拖动取消解除 busy；相机写盘防抖；真实定位同时尝试 GPS/网络并丢弃过期选择；开始前固定路线快照；大 GPX 后台编码；嵌套主题重置文字颜色。上述最终收尾在用户断开手机后完成，手机上仍是此前的中间构建，应在下次验收时覆盖安装最终包。

首次部署 LSPosed 仍需按模块流程激活；本轮兼容现有 0.3.0 模块，不需重装或重启已激活模块。设备验收可显式运行 [verify-device.ps1](../scripts/verify-device.ps1)，脚本无自动重连、网络设置或重启操作。
