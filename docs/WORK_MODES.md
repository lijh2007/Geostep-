# 工作模式与注入回读校验

适用版本：主应用 **0.6.3** · LSPosed 模块 **0.3.21** · Root 载荷 **0.1.4**

本文说明「标准 / LSPosed / Root」三种工作模式的区别、App 如何判断某种模式**真的可用**，以及开始模拟后如何确认**位置与步频确实被注入**。

---

## 1. 三种模式能做什么

| | 标准模式 `provider` | LSPosed 模式 `xposed` | Root 直连模式 `root` |
| :--- | :--- | :--- | :--- |
| 位置模拟 | ✅ 系统模拟位置（AppOps） | ✅ 系统级 Hook，全通道 | ✅ 状态镜像 + 注入式载荷（不写 system_server） |
| 步频 / 计步传感器 | ❌ 不注入传感器 | ✅ `STEP_COUNTER` / `STEP_DETECTOR` | ✅ 需先对目标 App 注入一次（0.6.3 实测通过） |
| 需要 root / 框架 | 否 | LSPosed（libxposed API 102） | KernelSU / Magisk（su） |
| 停止后恢复真实位置 | 立即 | 立即（无需重启） | 立即（无需重启） |
| 与其他框架共存 | — | 与 Root 模式互斥 | 需无 LSPosed 驻留 |

**步频只在后两种模式生效。** 标准模式下即使把「模拟步频」调到固定值，也不会有人收到计步事件——参数面板会用红字提示，切换模式后自动恢复。

---

## 2. 在哪里切换

1. `工具（底部第二页） → 工作模式`：显示当前模式与该模式的实时状态，点开进入偏好设置。
2. `偏好设置 → 运行模式`：三个选项，每项下方一行状态：
   - **可用** —— 该模式的关键检查项全部通过；
   - **未检测** —— 还没跑过自检（进入设置时会自动跑一次）；
   - **具体原因** —— 例如“未检测到 LSPosed 模块”“未授予 Root 权限”“未开启模拟位置信息应用”。
3. 右下角 **重新检测**：手动重跑全部模式的自检（安装/升级模块、授权 Root 之后点一下即可）。

**切换规则**：仅在「未在模拟」时允许切换；点选后先跑该模式自检，**关键项不通过就不切换**，并用提示条告诉你缺哪一项。这样不会出现“切过去了但一直不生效”的状态。

---

## 3. 各模式的关键检查项（切换门禁）

| 模式 | 关键项（任一失败即阻止切换） |
| :--- | :--- |
| 标准模式 | 定位权限；「模拟位置信息应用」AppOps |
| LSPosed | 定位权限；LSPosed 模块已安装；模块版本 ≥ 0.3.1；系统控制通道可达；系统定位钩子已安装 |
| Root 直连 | 定位权限；Root 权限；状态镜像可写（失败才阻止，见 §4） |

非关键项（如模块版本低于 0.3.17）不会阻止切换，但会在状态行里显示为提示。

---

## 4. 注入回读校验：怎么证明“真的生效了”

控制面只保证 SET 命令被**接收**（`enabled` / `revision` 一致），并不保证模块真的把坐标写进了 Location、把步频写进了计步器。所以 0.5.0 增加了回读校验：

- **触发时机**：开始模拟后 2.5 秒首次回读，之后每 10 秒一次；也可在主界面点状态条或「校验」按钮立即复查。
- **比对内容**：
  1. **模拟坐标回写** —— 模块回执里的 `lat/lng` 与刚下发的坐标比，haversine 距离 ≤ **2.5 米** 视为通过（标准模式下改为从 `LocationManager` 读回 `getLastKnownLocation`）。
  2. **模拟速度回写** —— 模块上报的 `speed_mps` 与下发速度差 ≤ **0.05 m/s**。
  3. **模拟步频回写** —— 模块上报的 `cadence_spm` 与“按当前速度/配置算出的期望值”完全相等（公式见 [STEP_CADENCE.md](STEP_CADENCE.md)，App 与模块共用 `StepCadence`）。
- **状态显示**：主界面地图下方状态条
  - 绿色 `位置与步频注入已确认`（或自动步频的“自动步频 92 步/分已生效”）；
  - 红色 `注入未生效：<具体原因>`，展开可见每项结论。
- **常见失败与含义**：

| 状态文案 | 含义 | 处理 |
| :--- | :--- | :--- |
| 模块版本低于 0.3.17，未上报速度/步频 | 模块 APK 太旧，没有上报实际生效值 | 升级模块到 0.3.17 并重启 |
| 模块状态回执已过期 | 模块重启或未推送 | 停止后重新开始模拟 |
| 未读到模块状态回执 | 模块未加载 / 未勾选作用域 | 在 LSPosed 里勾选 System Framework 并重启 |
| 回读坐标与下发值相差 N 米 | 坐标被别的模块覆盖，或作用域没覆盖目标 App | 检查作用域与冲突模块 |
| 模块回执步频 X，预期 Y | 模块侧配置未更新（少见） | 重新开始模拟；仍不符请附诊断日志反馈 |
| 标准模式…不注入传感器 | 模式选错 | 切到 LSPosed 或 Root |

## 5. 线协议（供机器人脚本使用）

状态 Provider `content://com.geostep.app.status` 新增两列：

| 列名 | 类型 | 缺省（旧模块） | 含义 |
| :--- | :--- | :--- | :--- |
| `speed_mps` | Real | `NaN` | 模块当前实际生效速度 |
| `cadence_spm` | Integer | `-1` | 模块当前实际生效步频（0 = 静止不出步） |

控制面 `sendExtraCommand` 的 SET 仍只多一个可选字段 `step_cadence_spm`（0 = 自动，1–300 = 固定），参数细节见 [STEP_CADENCE.md](STEP_CADENCE.md)。

模块版本：`MODULE_VERSION = "0.3.17"`；主包判断“是否上报速度/步频”用 `XposedEngine.MIN_CADENCE_MODULE_VERSION`。

## 6. 验证记录

- `core:engine` 的 `InjectionVerifierTest` 覆盖坐标容忍/超差、速度不符/未上报、固定步频不符、自动步频按速度推算（1.0 m/s → 92 步/分）、静止期望 0、缺回执时给出原因、三检查项、haversine 精度。
- `module` 侧既有 73 个用例保持通过（`StepCadence` 改为委托 `core:model` 后行为不变）。
- 0.6.3 全量单测 **238 通过**（module 78、core:engine 65、core:route 47、core:model 25、app 14、core:data 9）。
- 真机验证（Redmi K60 / HyperOS / Android 17）：标准模式 `last mock location` 为下发坐标且 `vel=1.4`；Root 模式注入探针 App 后收到间隔 495–510ms 的 `TYPE_STEP_DETECTOR` 事件（120 步/分），日志 `step pump: delivered=20 type=18 spm=123`。
- LSPosed 模式：模块尚未在框架侧启用（`/data/adb/lspd/log/*` 无 Geostep 记录），该项仍待用户启用后复测。

## 7. Android 16 / 17

- `compileSdk` / `targetSdk` = **36（Android 16）**，`minSdk` = 26。
- Android 17：标准模式与 Root 注入式模式已在 Redmi K60（HyperOS / Android 17）上真机跑通；LSPosed 模式沿用同一套 libxposed API 102 入口，尚未在该机复测。
- 新增的两列状态与可选 JSON 键都是**加性**变更：旧模块、旧回执、旧主包互不影响。
