## 3. 本次明确修复

| 问题 | 当前处理 |
|---|---|
| 冷启动清理与首次开始并发，首次点击被吞 | `GeostepApp.ready` 初始化屏障，开始前等待清理与初始设置装配 |
| 启动 busy 标志或超时后无法恢复 | 会话事务与有限超时；失败可见，停止意图不会被忙碌请求静默丢弃 |
| 停止与仍在运行的 tick 竞争 | 先取消并等待 tick；引擎操作串行化，再发送停止并验证结果 |
| 旧帧在停止后重新启用模块 | 客户端期望开关、发布锁、递增 revision 与模块旧 revision 拒绝 |
| 停止异常被视为已关闭 | 保持未确认状态并重试；只有确认后发布 Idle；保留可操作停止入口 |
| 非协作 Binder 调用拖住超时 | 引擎工作与等待超时分离，迟到完成后补充清理 |
| 模块失联后一直模拟 | 心跳续租与模块 15 秒失联租约；模块重启默认禁用 |
| 模块已启用但主应用将回执误判为未启用 | `ContentValues` 布尔回执改用 `getAsBoolean` 读取，修正 `enabled` 与 hook 状态被 `getAsInteger` 误判的问题；设备端回执与位置测试通过 |
| 前台服务启动失败静默或残留 | 捕获异常、通知/消息反馈、服务收尾；进程重启不自动重播旧路线 |
| 运行参数仅存储、不作用于后续 tick | 控制器持续接收设置，速度、漂移等按当前设置推进 |
| 暂停恢复跳点、丢失 GPX 海拔 | 暂停继续持续静止上报，保留当前位置和海拔，继续重建计时基准 |
| 停止后更换选点，摇杆仍从旧位置开始 | 空闲时摇杆优先使用新选点；运行中使用当前模拟点 |
| 路线有数据但地图不显示 | 草稿与当前运行路线接入地图折线和预览 |
| 每次开始路线产生重复保存 | 保存与开始分开；新增命名、加载与重命名操作 |
| GPX 导入丢海拔/速度、区域格式导致小数逗号 | 保留详细点，SAX 解析与区域无关数值格式；禁用外部实体 |
| 路线与点分开写入留下不完整数据 | Room 事务覆盖保存/删除，读取按 seq 排序 |
| 冷启动默认历史上限误删用户数据 | 裁剪订阅持久化真实设置，避免 StateFlow 初始默认值触发删除 |
| 网络规划/文件导入迟到覆盖新草稿 | 草稿 revision 校验，拒绝过期结果 |
| 权限提示不能操作、日志为固定快照 | 权限请求与系统设置跳转接通，诊断定期刷新并可导出 |
| 悬浮窗仅有摇杆且无关闭/位置记忆 | 新增控制条、拖动/边界处理、位置保存；停止通知后随会话自动关闭 |

### 验证边界

15 秒进程死亡租约已通过独立设备检查：在测试应用报告 `LEASE_READY` 后启动独立 `uid=1000/package=android` 观察者，再执行 `am force-stop com.geostep.app`。强制停止后约 14.9 秒的样本仍为 `isMock=true/testBeijing=true`，约 15.9 秒的样本开始返回 `location=NULL`，之后样本持续为空。此时主应用进程和前台服务均不存在；没有重新打开主应用来触发清理。结果符合 15 秒租约加 1 秒采样分辨率，证明系统不再返回旧模拟点。设备当时没有可用的真实 GPS 缓存，因此不将空位置描述为已获取新的真实坐标。

原始证据：[独立观察日志](../../_tools/v2-lease-observer.log)、[强制停止时间](../../_tools/v2-lease-force-stop-at.txt)、[租约测试启动日志](../../_tools/v2-lease-start.log)。租约启动日志最后的 `Process crashed` 是本次主动强制停止测试进程的预期结果，不是自然崩溃。

本次验证覆盖表内路径；其他 ROM、长时间后台/锁屏、各类权限撤回、所有文件选择器和悬浮窗旋转组合未穷尽。这些属于后续兼容性扩展验证，不扩大本次已通过的结论，也不列为尚未完成的核心功能。

## 5. 运行条件与限制

1. 默认地图使用 osmdroid + OSM France HOT；本次为非商业个人开发验证。地图、Photon/Nominatim 搜索、OSRM 规划依赖公共服务与网络，没有高德 Key。计划用于其他用途时需重新选择符合用途和流量规模的地图服务。
2. 在线路线使用 OSRM 驾车道路。速度预设不改变道路规划 profile；GPX 的分段速度优先于默认速度，路线页预计时长为参考值。
3. 主应用配置间隔为 200–2000 ms。LSPosed 主动监听器上报目前固定为 1000 ms，不能宣称已经与该滑块完全联动。
4. 模块需要兼容 libxposed API 102 的宿主，启用「系统框架 / system」后重启。ROM 的位置接口差异仍需验证；不保证任意 Android 设备或应用行为完全一致。
5. GPX 导入上限为 8 MB / 100000 点；目前合并点序列，不保留多轨迹分段和原始时间戳。导出使用扩展保存分段速度。
6. 设置 JSON 版本为 1，最大 64 KiB，完整校验后原子写入；不切换引擎、不包含数据库。收藏与历史导出没有逐点名称往返恢复能力。
7. 当前未实现：脚本引擎、native HAL、传感器/步频注入、基站/WiFi/SIM 模拟、按应用独立模拟、多地图供应商、语言切换、私有分享码。对应功能没有占位式可点击入口。
8. 位置始终保留 mock 语义。停止以系统清理或模块回执为准，失败必须继续显示未确认状态。

## 6. 复现入口

构建命令与安装路径见 [README](../README.md)。标准模式先在开发者选项选择 Geostep 为模拟位置应用，按「输入坐标 → 开始 → 路线 → 暂停 → 继续 → 停止」执行；`adb shell dumpsys location` 用于核对坐标、速度和 mock provider 清理。LSPosed 使用 `adb logcat -s GeostepModule` 配合主应用诊断日志核对模块端行为。
