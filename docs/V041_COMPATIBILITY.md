# 0.4.1 / 模块 0.3.1：外部定位兼容排查

本次修复来自用户反馈：多个外部入口未取得预期位置。用户不提供目标应用、网站或小程序名称，因此目标入口由用户自行测试；开发侧不读取这些入口或记录其身份。

## 已确认的事实

- 参考包是 **Fake Location 2.1.4**，不是 2.1.7。设备当时安装的版本与工作区一致。
- 当时 Geostep 已选 `xposed`，LSPosed 2.2.1/API 102 处于激活状态，系统模块实际接收了 SET 命令。因此不能直接把原问题归因于未重启。
- 原验收中“系统接口测试通过”不等于“所有外部 SDK 和业务入口通过”；本项目尚未完整复刻 2.1.4 的全部注入层。
- 2.1.4 的 [tt0.java](../../apk/FakeLocation_2.1.4/jadx/sources/defpackage/tt0.java) 用 Root 部署原生库，[NativeBridge.java](../../apk/FakeLocation_2.1.4/jadx/sources/com/yinshibai/location/NativeBridge.java) 由 XposedModule 加载；不能把 Root 授权弹窗直接当成独立免模块引擎的证据。当前 Geostep 仍提供标准模拟与 LSPosed 两种引擎，没有冒充独立 Root 注入模式。

## 独立进程基线

新增 `:probe` 测试 APK，包名 `com.geostep.probe`、独立 UID，只使用公开 LocationManager 与 WebView Geolocation。它不调用 Geostep 的控制通道，不读取其状态提供器，也不使用内置模拟坐标作为位置来源。

受控点设为 `39.9087, 116.3975`。原模块 0.3.0 的 [原始报告](../../_tools/external-probe-baseline.json) 与 [检查脚本](../../_tools/check_external_probe.py) 显示：

| 路径 | 基线结果 |
|---|---|
| GPS / 网络 / 融合的 last-known | 坐标匹配受控点 |
| 连续位置更新 | 坐标匹配，但部分 network/fused 回调被错误标成 gps |
| GPS 一次性 current-location | 20 秒检查窗口内没有回调 |
| 网络 / 融合 current-location | 返回受控点 |
| 独立 WebView 的 Geolocation | 返回受控点 |

这个基线证明系统注入并非完全无效，也证明其覆盖有缺口。它不代表用户不公开的目标入口已通过。

## 本次修复

1. 模块 0.3.1 桥接 `ILocationCallback`：先经过框架权限检查，补充一次性定位回调，保证只投递一次并清理原来的等待请求。
2. 连续监听器按其请求的 gps/network/fused 类型构造输出，不再统一标成 gps。
3. 补充 `Location.writeToParcel` 路径，覆盖直接传输缓存位置、未经过 LocationResult 的返回方式。
4. 主应用 0.4.1 分开检查模块安装、实时控制通道、系统钩子、已加载版本。安装新模块但仍运行旧版本时阻止误判为已更新，明确提示手动重启。
5. 诊断只统计历史查询、一次性查询、连续订阅和模块投递次数，不记录调用应用、网址或小程序身份。
6. 可选“兼容性测试格式”：只调整本工具生成位置的模拟标记，默认仍保留标准标记。标准 Test Provider 继续遵循 Android 自身的模拟标记。此选项不修改 IP、网络、定位权限，也不伪装 Root 环境。

## 用户手动验收

本轮模块有更新，与前一轮仅更新地图不同。需先覆盖安装主应用 0.4.1 和模块 0.3.1，再由用户自行重启手机并恢复热点。开发工具不自动重启、不运行网络恢复脚本。

1. 打开“权限与诊断”，确认已安装与加载版本都是 0.3.1，控制通道和系统定位钩子就绪。
2. 在 LSPosed 模式下选点并开始。到自己的目标入口手动测试。
3. 若目标拒绝标准模拟标记，可先停止，再在设置中开启“兼容性测试格式”，重新开始测试。
4. 反馈只需描述：仍为原位置、定位失败、位置改变但被拒绝、或显示地区未变。无需提供应用名称或网址。诊断计数可辅助判断是否调用系统位置接口，但不能单凭计数确认目标最终接受。

按 IP 推断的地区不由定位坐标决定。自带网络定位 SDK、历史缓存或其他检测逻辑也可能影响结果，因此本轮不宣称对所有业务入口生效。

## 验证状态

当前主应用、模块和独立探针构建及静态检查通过，JVM/debug 单元测试为 **109 项、0 失败**，见 [最终检查日志](../../_tools/compat-041-release-check.log)。设备测试入口补入 GPS/network/fused 的一次性请求检查，需在用户安排重新连接后运行。

上述独立进程报告是**修复前基线**；0.3.1 新模块需要用户手动重启加载后复测。未将编译通过或旧版本报告当作新版本外部兼容已通过。首次安装时手机已断开；用户重新连接后，主应用 0.4.1 和模块 0.3.1 已成功覆盖安装，并核对设备 APK 的 SHA256 与发布文件一致。诊断页实测显示「已安装 0.3.1，系统加载 0.3.0」，正确提示等待用户手动重启。没有执行自动重启或热点操作，当前模拟为停止状态。
